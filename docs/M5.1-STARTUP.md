# M5.1 — Reliable startup and recovery

Candidate on `m5.1/reliable-startup`, based on main `c15ccb69cd5930afc941a46f79671cfedd144593`.
Production remains unchanged. Steering acceptance, merge and production installation are separate gates.

The selected mechanism is a native **user LaunchAgent in the Aqua login session**. It runs
`/usr/bin/sandbox-exec -f <retained-profile> <release>/oldphonedeck --managed-startup
--config-dir <existing-config> --port 8045` directly. There is no supervisor process,
LaunchDaemon, root service, new dependency or independently confined Git worker.
Launchd starts it at login and restarts unsuccessful exits, throttled to 30 seconds.
A successful exit is left stopped; use `kickstart` to resume. Logout ends the user session;
service availability before login is not promised. Sleep suspends normal Mac availability.

## Entry point and protections

`--managed-startup` is opt-in. It holds `startup.lock` using nonblocking `flock` for the
process lifetime. A leftover file is harmless: the kernel releases the lock on exit.
Never delete/replace the lock to recover. Each manual start of the managed installation
must use this flag. Legacy binaries do not participate in its lock; an occupied HTTP,
HTTPS or WSS port still prevents a healthy managed startup.
The preflight reserves IPv4 and IPv6 sockets on all three ports briefly. macOS can
allow a wildcard reservation beside an address-specific listener; concurrent processes
can also race the check. Actual asynchronous bind failures are therefore fatal too.
A conflicting port owner is never stopped; candidate listeners close on process exit.

Existing strict V2, nonempty token, TLS files and matching LAN address are required.
Managed TLS loads the retained identity directly and never generates certificates.
The production sandbox still denies token/TLS writes and OpenSSL execution. No file
migration, app action, Shortcut approval or credential rotation is part of startup.
Missing/corrupt configuration, missing credentials, changed IP or invalid identity require
operator correction. A changed IP is a visible failure, not automatic TLS replacement.
Seven controls, IDs/order/parameters/titles, widgets and approval state stay in their
existing files. The only additional configuration-directory artifact is `startup.lock`.

HTTP/HTTPS/WSS state callbacks report listener readiness; startup waits at most 30 seconds
for all three. Required listener failure exits unsuccessfully for native restart. This
is startup/lifecycle recovery, not a hang watchdog or ongoing application health monitor.
The readiness message explicitly requires an authenticated health check. Raw stdout is
`/dev/null` because the existing banner includes authenticated URLs. Fixed startup
messages go to a private stderr log; no credential values are included in those messages.
Managed startup suppresses the legacy Accessibility prompt; existing user-session
integration permissions must be retained and separately verified after an approved cutover.

## Stage without installing

`tools/make-launchagent.py` only generates a plist and an empty `0600` stderr log in a
new `0700` directory. It does not install, bootstrap, stop or restart anything. Supply
absolute, reviewed release/profile/config/cwd paths. Keep the generated log path stable
when moving the plist. A release includes its adjacent SwiftPM resource bundle.

```sh
python3 tools/make-launchagent.py \
  --binary /absolute/release/oldphonedeck \
  --profile /absolute/retained/production.sb \
  --config /Users/adriantorres/.oldphonedeck \
  --cwd /absolute/release \
  --output /absolute/new-private-staging-directory
plutil -lint /absolute/new-private-staging-directory/local.phonedeck.plist
```

Production installation is **not authorized by this task**. Before an approved cutover,
record exact executable/resource/profile hashes, process PID/start/UID/cwd/arguments and
8045/8047/8048 owners. Preserve the existing full configuration with ACLs/xattrs using
`ditto --rsrc --extattr --acl`, including latest V2 edits, widgets, token/TLS and approval
state (absence is state). Retain the previous executable, bundle, sandbox and launch receipt.
Stop only the verified old process; never install the job beside the current nohup process.
The generator does not replace this identity and backup gate.

After approval, place the reviewed plist in the user's `~/Library/LaunchAgents` and use
`launchctl bootstrap gui/<uid> <absolute-plist>`. This binds the job to the logged-in user,
without sudo. Verify exact job PID/executable and all three listener owners, authenticated
HTTP/HTTPS `/info` and `/launcher`, the retained certificate fingerprint, and authenticated
WSS upgrade plus ping after the authentication deadline. Compare full configuration and
protected-state inventory. A loaded job or listener banner alone is insufficient.
Reboot/logout and real integration permissions still require separately authorized human
acceptance; the isolated tests do not claim them.

## Diagnose and recover

1. Read `launchctl print gui/<uid>/local.phonedeck` and the private `startup.stderr.log`.
   Last exit 1 plus a startup message identifies missing state, address mismatch, lock,
   occupied port, TLS load or listener failure. Use `lsof` to identify owners; never kill
   by name or free ports by guessing. Native throttle may delay restart by 30 seconds.
2. For persistent failure, `launchctl bootout gui/<uid>/local.phonedeck` prevents restart.
   Confirm the managed PID is gone and its listeners released. Preserve logs and latest
   user state. Do not remove the lock file, reset V2 or restore an old backup over new edits.
3. Correct only the proven cause. Restore missing files only from a verified current
   recovery source. A LAN/TLS mismatch, permission dialog or credential issue needs its
   own authorization; do not rotate, weaken the sandbox or fall back to HTTP-only.
4. If still loaded after correction, use `launchctl kickstart gui/<uid>/local.phonedeck`.
   If booted out, bootstrap its retained reviewed plist. Use `kickstart -k` only for an
   explicitly authorized restart. Repeat authenticated HTTP/HTTPS/WSS and continuity checks.
5. To revert an approved installation, boot out the job and remove its installed plist
   from `~/Library/LaunchAgents` to prevent next-login activation. Reverify ports are free,
   then use the retained previous binary/bundle, unchanged sandbox and exact old launch
   procedure with the latest compatible V2 state. Recheck health and protected state.
