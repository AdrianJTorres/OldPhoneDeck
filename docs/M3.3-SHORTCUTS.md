# M3.3 operator setup and acceptance boundary

M3.3 adds explicitly approved UUID Shortcuts to the existing seven-key editor.
Implementation authorization does not authorize real execution or production deployment.

The server reads `shortcut-approvals.json` from its selected `--config-dir` at startup.
It does not create this file. Missing, unreadable, invalid, duplicate, oversized, symlinked,
wrong-owner or group/other-accessible files mean no approvals. Use a private directory
(mode 0700) outside Git, with an operator-authored mode 0600 file containing an array:

```json
[{"uuid":"REPLACE-WITH-EXPLICITLY-APPROVED-UUID","label":"PhoneDeck M3.3 UUID Test"}]
```

The placeholder deliberately grants nothing. Replace it only with an explicitly approved
UUID. The isolated preview contains only the test UUID supplied by Steering; its private
file and the personal UUID are excluded from Git. Restart the isolated server after an
operator approval edit. There is no phone/API approval-management operation and discovery
never populates this file. A saved key's title is display data, not authority.

The editor lists apps and approved Shortcuts together. Hold a key to edit. Remove one entry
before adding when all seven positions are occupied; ▲ moves a whole entry earlier.
Unavailable applications, unknown actions and unapproved/missing Shortcuts remain visible
in their saved positions. Save commits the entire ordered array with the observed revision;
Cancel leaves the document unchanged. Widget flags share the same revision and transaction.
A stale editor must reload before saving. Legacy app-only clients refuse mixed documents.

Tapping an authorized Shortcut reserves the single execution slot, checks current UUID
availability and then runs asynchronously. The initial five-second catalogue check is
included in Running feedback, followed by a maximum 30-second execution. Availability
starts as unchecked; a run always checks afresh, including after a previous missing result.
The phone receives Running, Completed (CLI exit 0), Failed, Timed out — outcome unknown,
Busy, Not authorized or Unavailable. Completed is not proof of the Shortcut's effects.
Network loss or replacement of the latest status also leaves an unknown outcome. Each
execution/status HTTP request has a five-second client watchdog; a hung request is aborted
and late responses are ignored. This does not cancel an already dispatched Shortcut. Execution
is never automatically retried; polling is GET-only. After a timeout inspect the Mac before
choosing whether to run again. Killing the CLI cannot guarantee cancellation of Apple's
external Shortcuts engine or undo side effects.

For consent setup, keep the harmless test Shortcut installed under its approved UUID in
the same macOS user account as the server. Run the intended binary from the intended login
session/launch context. When Steering separately authorizes a server-triggered acceptance
run, have the Mac visible and unlocked so a human can inspect and answer any Shortcuts,
output-sharing or Automation prompt. Grant only the permission the harmless test actually
needs. Do not change TCC databases, reset permissions, assume Terminal's Allow Always covers
the server, or use another launch context as acceptance evidence. If it stalls, retain the
unknown-outcome boundary and investigate before any separately authorized manual retry.

The isolated HTTPS preview uses its own directory, token, CA and ports. Trust only that
preview CA on the test phone if needed; no production token or TLS rotation is involved.
The private local launch page contains the preview URL and must not be committed or copied
into review messages. Preview checks may read/save synthetic configuration and test denied
UUIDs; they must not POST the approved test UUID until separately authorized. Automated
checks and a working preview do not establish physical acceptance.

Required physical acceptance remains PENDING: explicit removal/addition and Save/Cancel;
all retained applications and widget preferences; unknown/unavailable entries in place;
portrait/landscape/Home Screen; separately authorized server-context harmless UUID execution
and consent handling; accurate Running/completion or timeout feedback. Steering decides
acceptance after one independent T3 review and the physical evidence.
